# SOFTMAX unit (SmolVLA -12392 attention, integration contract 1.0)

The unit turns FP32 attention scores into the int16 P rows of the P·V GEMM. Per row it writes `q` in
[0, 32767] and one FP32 scale, so `P = q * scale` with `scale = RN(1 / sum q)`. It runs opcode SOFTMAX (0x40)
of `fpga/kernels/CONTRACT.md` (version 1.0) as a mode function of the float_top sequencer.

**Status (2026-11-21): host-verified and csynth'd. No Vivado run, no cosim, no board run.**

- The host build runs the HLS source. It is bit-exact against the torch golden executor (`smx_emu.run_cmd`) on
  51 cases, both as sequential processes and as threads on FIFOs bounded at the pragma depths.
- csynth at 4.0 ns: 342 MHz estimated, every loop II = 1.
- Area: **8,614 HLS LUT, 614 over the contract's 8k cap.** DSP is 10 of 16, BRAM36 is 4 of 4. See Resources.

## Arithmetic (exact definition: `smx_emu.py`)

Per row of L scores x, with the score multiplier p0 (1.0 in the contract's list: the 1/8 rides in Q's stored
scale, p4 = -3):

1. `c = fl32(max(p0, 2^-126) * fl32(log2 e))`. It is an integer RNE product in the prologue, checked against the
   host FPU on 3,054,470 p0 patterns. `Mc, ec` = c's significand rounded half up to 17 bits, and its exponent.
2. **Mask** (F_MASK): key k is visible to row n iff `0 <= E[k] <= D[n]` (int32, exact).
3. **Row max** m over the visible keys, on FP32 total-order integer keys.
4. `u = min(fix(m) - fix(x), 2^26 - 1)`, where `fix(x) = trunc(x * 2^(ec+21))` on 47 bits plus a sign,
   saturating. Masked keys, pad rows and `d >= 2^26` get the saturated u.
5. `t = u * Mc` (Q.37). `e23 = T23[ix] - ((S13[ix] * flo) >> 13)`: one 1024-entry table plus linear
   interpolation. Then `q = ((2 e23 >> I) + 257) >> 9`, which is 0 for every I >= 17 without a select.
6. `scale = RN(1 / sum q)`: a correctly rounded radix-4 restoring divider, checked on all 2^23 possible sums.
   A zero sum gives 1.0.

From the score bits to the scale bits the arithmetic is integer, so the host build is the hardware's arithmetic.
Applying the contract quantizer to `fl32(q * scale)` gives back the same q and scale (review: 0 differences on
874 real rows).

## How it works (one DATAFLOW region, every loop II = 1)

| process | what | pipeline depth |
|---|---|---|
| `reader` | xmem: rank_k (once per item, or once per command when its stride is 0), then per block of <= 256 rows its rank_q and the scores. Scores are one burst per block when the A pitch is 4 L, else one per row. Visibility, the row max (two partial maxima), the words + 4 visibility bits into a one-row FIFO (64 x 132, LUTRAM) | 15 |
| `compute` | per row: one setup cycle (the max through lane 0's fix shifter), then L/4 words. 4 lanes of fix, 2^x and q (2 table BRAM36, 4 x 2 DSP), the row sum. Rows [N, NP) and the pad lanes give sum 0 | 14 |
| `divider` | RN(1/sum): 1 load + 13 radix-4 steps per row; 4 scales per word. Bit 23 of the sum stream ends the command (no counters) | 5 |
| `writer` | ymem: per block, the P rows as one burst (when the C pitch is 2 L, else one per row), then the block's scale words as one burst | 3 |

FIFO depths and why (each is checked by the bounded model):

- `xs` = 64 words, one row of L = 256: compute needs the max before the row.
- `rq` = 64 words, one block's scales: the writer reads them after the block's rows.
- `eq` = 16, `mx` = 4, `sq` = 4.

Where the rest goes:

- Four 48-bit fix shifters (588) and their sign xors and subtracts, about 1.2k. Exactness needs all 47 bits: two
  saturated or nearly equal scores far from 0 must still differ exactly.
- The address and loop logic of reader and writer: about 2k, five 36-bit pointers each, plus the HLS-generated
  64-bit burst address.
- HLS books 32 LUT for every value it delays through a pipeline (10 such values in compute).

Options left (not done):

1. The contract's fallback 1: fold the softmax into the row unit, sharing its reader, writer and row buffer.
   Est. -2.5k, the integrator's call.
2. The contract could carry c's `(Mc, ec)` instead of p0, so the host computes `c`: about -0.2k.
3. `BIND_OP op=add impl=dsp` would move the pointer adders to DSP, but it is not a valid directive for this
   device in HLS 2022.2. Probe v12: with it, every bind directive of the file is rejected.

### Full policy (-12392, 3 replay frames, `policy_check.py`, run 2026-11-21)

Every attention softmax of the policy (vision, LM prefix, expert self and cross) runs the unit's emulation
with the contract's arithmetic:

- the scores arrive already x 1/8, and p0 = 1.0;
- masks are int32 rank vectors (all 1,584 masked calls converted and checked);
- fully masked rows give scale 1.0.

The table gives max |chunk - ref_chunk_raw| in normalized action units; the gate is 0.05.

| frame | orig | explicit FP32 | smx (P·V FP32) | smx_pv16 (P·V as the contract's int16 GEMM) |
|---|---|---|---|---|
| 0 | 5.13e-6 | 3.52e-6 | 7.62e-5 | 1.38e-4 |
| 3563 | 4.62e-7 | 3.58e-7 | 2.69e-5 | 2.76e-5 |
| 7489 | 4.77e-7 | 3.58e-7 | 4.22e-5 | 4.01e-5 |

- **smx_p0.** p0 = 1/8 on the raw scores gives the same chunk as smx, bit for bit.
- **smx_pv16.** P·V computes `X = q`, `s_tok = scale`, `W = V^T` quantized by the contract quantizer per
  (head, channel), and `y = ftz(ftz(fl(acc) s_row) s_tok)`. The expert's self-attention runs as two GEMMs (prefix,
  then suffix with F_ACC).
- **Against T-P1.** The targets are <= 0.006 on frame 0 and <= 2e-4 on the benign frames. This is the softmax's
  share only; Q·K^T stays FP32.

- **No C/RTL co-simulation** (csim is broken here). The deadlock argument is checked by the threaded
  bounded-FIFO model, not in RTL.
- **The time model is an estimate.** The KR260's DDR latency and burst efficiency on the io port are
  unmeasured.

  row unit and the engine (sharing the io adapter) is unknown.
