# norm_residual: fused residual add + LayerNorm / RMSNorm + int16 quantization

The future NORM mode of `float_top` (sequencer `OP_NORM` 0x30). One pass over each row, held on chip:

    y = A (+ B)                                 FP32 IEEE add (the residual add)
    D <- y                                      FP32, the new residual stream          (F_SUM)
    z = LayerNorm(y; gamma, beta, eps)          vision, eps 1e-6                       (F_LN)
      | RMSNorm(y; weight, eps)                 LM / expert, eps 1e-5
    C <- q = int16(z), F <- per-row scale s     the next linear's X operand            (F_QOUT)
    C <- z FP32                                 vision post_layernorm (pixel shuffle next)

Status: C++ core done and bit-exact against its torch model on 19 DDR-image cases (6 from real -12392
activations). csynth done at 4.0 ns and 3.333 ns. Full-policy effect measured on -12392's 3 replay frames.
Not done: no Vivado run, no RTL co-simulation (csim/cosim are broken here), no board run.

## Arithmetic (exact definition; `nr_emul.py` is the reference, `tb_nr.cpp` checks the C++ against it)

Per row of K values (K % 8 == 0, 8 <= K <= 1024):

1. **Statistics, exact.** Block floating point: `Emax` = max exponent field of the row;
   `Y_i = round_half_away(m_i * 2^(1 + e_i - Emax))` (24-bit significand m_i, |Y_i| < 2^25; e_i = 0 counts as 0);
   `S = sum Y_i`, `Q = sum Y_i^2` exactly (48 / 64-bit integers); `num = K Q - S^2` (LN) or `K Q` (RMS), exact
   (< 2^71). So the variance has no cancellation and no summation-order error. The only rounding is Y_i at
   2^-25 of the row max.
2. **Row scalars, FP32, round to nearest even, one op at a time:** `invK = recip_nr(K)`, `invK2 = recip_nr(K^2)`
   once per call; `var = ldexp(i2f(num) * invK2, 2 (Emax - 151))`; `mean = ldexp(i2f(S) * invK, Emax - 151)` (LN, else
   0); `rstd = rsqrt_nr(var - (-eps))`. `i2f` is exact integer -> FP32 RNE; `ldexp` is an exponent add (results
   below 2^-126 flush to +0). `recip_nr` / `rsqrt_nr` use a 128-entry seed ROM plus two Newton-Raphson steps
   (FP32 mul/sub, no FMA): max relative error 1.46e-7 / 1.53e-7.
3. **Normalize, FP32:** `z = ((y - mean) * rstd) * g + b` in that order (RMS: b = 0, mean = 0).
4. **Quantize:** `A = max|z|`; `inv = trunc17(fl(recip_nr(A) * 32767))` (a 17-bit significand), `s = recip_nr(inv)`;
   `q = clamp(rne(z * inv), +-32767)`. The product z * inv is exact (24 x 17 bits, one DSP per lane) and rounds
   half to even. The next linear sees `q * s`. A row with A < 2^-100 (e.g. an all-zero RMS row) gets q = 0, s = 0.
   This is not bit-identical to the quantize kernel's `s = fl(A / 32767)` definition. Both put the
   dequantization error at the int16 step (1.53e-5 of the row max). The engine only needs some s_tok.

Denormals: the FP32 cores flush denormal inputs and outputs, while the C model and the torch model keep them. Real
activations are never denormal; the test vectors contain none.

## Interface

### Registers (`nr::Cfg`; the standalone `nr_top` exposes each field as an s_axilite scalar, in this order)

| field | meaning |
|---|---|
| `flags` | `F_QOUT` 0x02, `F_RESID` 0x04, `F_SUM` 0x08, `F_LN` 0x10 (the sequencer's `seq_format.h` bits) |
| `K`, `N`, `B` | row length, rows per batch item, batch items (>= 1). `check_cfg` rejects K % 8 != 0, K < 8, K > 1024, N < 1, B < 1 (return 1, no DDR access) |
| `eps` | FP32 bit pattern (sequencer p0) |
| `a_off, a_pitch, a_stride` | A rows FP32 (hp0). Offsets, pitches and strides are in 128-bit words relative to the port base (sequencer mode: base 0, so `byte address >> 4`) |
| `b_off, b_pitch, b_stride` | B rows FP32 (hp1), read only with F_RESID |
| `e_off` | gamma: K FP32 values, then beta: K FP32 values (F_LN) (hp2), loaded once per call |
| `c_off, c_pitch, c_stride` | C rows: int16 (F_QOUT) or FP32 z (io, written) |
| `d_off, d_pitch, d_stride` | D rows: FP32 y (F_SUM) (io, written) |
| `f_off, f_stride` | F: per-row FP32 scales (F_QOUT) (io, written) |

`set_derived(c)` (two small multipliers, once per call) fills the trip counts and the read/write modes.

### Word formats (128-bit words, little endian, as `float_linear.h`'s io words)

* FP32 rows: value j of word i = element 4i + j, bits [32j+31 : 32j]. A row is K/4 words.
* int16 rows (C with F_QOUT): element k at word k/8, bits [16(k%8)+15 : 16(k%8)], two's complement. A row is K/8 words.
* Scales F: s of row n of a batch item at word n/4, lane n%4. The last word of each item is zero-padded, and
  the kernel writes whole words, so the F vector of an item must own its padding lanes.
* All addresses, pitches and strides are multiples of 16 bytes.

### DDR layouts and write modes (they decide the speed on the board)

Every m_axi burst ends with a write-response wait (HLS schedules `writeresp` at the burst loop's exit). So the
writer groups rows into chunks of up to 256 rows and uses as few bursts as the layout allows:

| mode | condition (`set_derived`) | bursts |
|---|---|---|
| `WM_REC` (records) | F_SUM, `c_off == d_off + K/4`, `c_pitch == d_pitch == K/4 + K/8` (FP32 z: `K/2`) | one flat burst per chunk: rows of [y FP32, K/4 words][q int16, K/8 words] |
| `WM_C` | no F_SUM, `c_pitch` = row words | one flat burst per chunk |
| `WM_ROW` | anything else (separate D and C regions, padded pitches) | two bursts per row |
| scales | F_QOUT | one burst per chunk, from a 256-entry on-chip buffer |

Readers: A (hp0) and B (hp1) are each read as **one burst per batch item** when the row pitch leaves a gap of at
most half a row (contiguous rows, or a residual stream written in records: the q words are read and dropped).
Otherwise they use one burst per row.

**Recommended layout for the sequencer:** residual stream and quantized X as records. In bytes: D slot =
`(R, pitch 6K)`, C slot = `(R + 4K, pitch 6K)`, F a contiguous 16-byte-aligned vector padded to 4 rows. The next
norm's A = the same D slot (pitch 6K), and the next GEMM's X = the C slot (int16 rows with pitch 6K). The
embeddings (first norm's A) and the sublayer outputs (B) stay contiguous.
`count_cost.py` puts records at 37.5-38.8 ms per chunk across the assumed write-response range of 0-150 clocks,
against 53-75 ms for separate D/C regions.

## Integration notes for float_top

* Call `nr::norm_residual_core(w0, w1, w2, ymem, c)` from the NORM branch of float_top's mode switch, after
  `check_cfg` and `set_derived`. The ports map as A over `w0` (hp0), B over `w1` (hp1), gamma/beta over `w2`
  (hp2), and every write over `ymem` (io). `xmem` and `w3` are unused. The bus interfaces stay as they are. The
  hp ports are only read, and the reads are ordinary bursts of at most 256 beats.
* The core is its own DATAFLOW region with `STABLE` on the config, so it can sit in a branch next to the
  engine's dataflow. HLS will give it separate m_axi request logic per process (A, B, gamma, writer). The
  standalone top's adapters (4 x 2.3k LUT) and s_axilite (1.9k LUT) are the ones float_top already has.
* In sequencer mode all bases are 0: `x_off = addr >> 4`, `x_pitch = pitch >> 4`, `x_stride = stride >> 4` from
  the command's slots (A, B, C, D, E, F as `build_smolvla.py` fills them: `norm(...)`); `eps` = p0. The sequencer
  must keep 16-byte alignment and K % 8 == 0 (768 / 960 / 720 all qualify).
* `NR_KMAX` (default 1024) sizes the gamma/beta tables and row FIFOs. `NR_FIFO_URAM` moves the four row FIFOs
  to URAM (8 URAM, 11 BRAM18 left) if BRAM is the tighter resource next to the engine.

## Throughput

Per call, the steady state is one row every `max(K/4, A words, written words)` clocks: 2.4-2.6 elements per clock
for add + norm + quantize rows (the io write port: 6 bytes per element), 3.5-3.9 elements per clock for first-layer
norms. Fill per call is about 3K/4 + 320 clocks (row scalars 126 + 103, loop depths about 90) plus the DDR latency.

Norm work per -12392 chunk (counted from the code by `policy_check.py`): 413 norm module calls / 31,973 rows /
24.28 M elements. Every norm except the first one of each stack fuses one residual add, so 400 of the 413 calls
include an add (vision 2 x 24, LM 32, expert 10 x 32).

| | calls | rows x K |
|---|---|---|
| vision LN (both images in one call: 512 rows) | 25 (23 add+norm, ln1[0], post) | 512 x 768 |
| LM RMS | 33 (final norm's output unused: skippable) | 81 x 960 |
| expert RMS | 10 x 33 | 50 x 720 |

`count_cost.py` (records layout): **9.50 M clocks = 38.0 ms per chunk at 250 MHz** (0.391 clocks per element). The
target is <= 50 ms. With separate D/C regions: 53 ms. The write-response wait (60 clocks), DDR latency (150)
and call overhead (100) are assumptions, not board numbers. DDR traffic in records layout: 16 bytes per element
(A 6, B 4, writes 6), about 10 GB/s at 2.56 elements per clock.

## Unverified / open

* Board timing, real DDR write-response and read latencies, Vivado BRAM mapping of the 128-bit FIFOs,
  post-route LUT/FF and clock. No RTL co-simulation: only the C++ is tested.
* Whether the sequencer adopts the records layout (owned by the sequencer agent). Without it the kernel runs
  at about 53 ms per chunk (estimate).
* The quantizer definition differs from `fpga/kernels/quantize`'s `fl(A/32767)` reference (same error class).
  If one shared definition is wanted, quant1 / qscal are the only parts to swap.
* LM layer 15's MLP and the LM final norm feed nothing (only the KV cache is used): skipping them saves 81 rows.
